# 計画：総合商社の新規事業計画（EV 部品と電池の循環事業）

> **架空の題材です。** 総合商社「東雲物産」、担当者、提携先はこの Project のために作った架空のものです。実在の商社・メーカー・人とは関係ありません。市場の数字は、出典つきの公開統計か「仮定」と明示したものだけを使います。

この文書は、PaoBub の dogfooding の計画です。Project の中身（`workflow.json`・`definition.json`・成果物・記録）は、工程を進めながらこのフォルダーに足していきます。

- 決めた日：2026-11-21
- 元の文書：[総合商社の新規事業計画 dogfooding シナリオ案](https://claude.ai/artifact/DXtLdoUhmdDMn8xPdp6kHG)

## ねらい

架空の総合商社の事業企画チームが、PaoBub の上で次の 3 つを作りながら新規事業計画をまとめ、最後にアニメーション付きのスライドで経営会議に諮ります。

1. 新しい工程定義「新規事業の企画」（`new-business-planning` 1.0.0、open-workflow-definitions）
2. マインドマップのエディタと、収支の道具（Open Editor Platform）
3. スライドのアニメーション（Open Editor Platform）

これまでの dogfooding（漫画・可変機・車・時計・スカイツリー・工場）は 3D が主役でした。今回は「言葉・数字・図」が主役です。

## 題材

**事業テーマ（2026-11-21 決定）**：EV の駆動ユニット（e-Axle）と車載電池を、使い終わった後に回収・診断・再製造・二次利用する循環事業を、タイと日本で始める。

- [factory-twin](../factory-twin/) の架空の e-Axle 工場を、再製造工場の下地に使います。
- 回収の拠点と経路は地図（geo）に、再製造工場は工場（factory）に、立ち上げの日程は日程（schedule）に置きます。

ゲート：

1. **G1 探索の終わり**（工程 2 の後）：事業企画部長が、仮説を確かめる価値があるかを決める。
2. **G2 投資委員会**（工程 8 の後）：財務 1 名と法務・リスク 1 名の両方の承認。収支の数字が前提から再計算できることを確かめ役が検査する。
3. **G3 経営会議**（工程 11）：スライドの数字が、受け入れ済みの計画書と収支の版に一致していること。

定義そのものもチームが作ります。進め方の工程で企画リーダーがマインドマップで「新規事業を決めるまでに何が要るか」を広げ、作業役が定義の JSON にし、財務と法務がゲートの条件を足します。途中で定義を 1.0 → 1.1 に上げる場面もわざと入れます。

## 作るエディタと道具

| 道具 | 新規か拡張か | できること | 使う工程 |
| --- | --- | --- | --- |
| E1 マインドマップ | 新規（mindmap-core と mindmap） | 放射・左右・ツリーの自動配置。Tab で子、Enter で兄弟、折りたたみ、枝の色と印。枝を項目（OP-01 など）に結ぶ。作業役の提案を枝ごとの差分で取捨。ホワイトボード・文書・スライドへの書き出し | 0, 1, 2 |
| E2 定義の見せ方 mindmap | 拡張（open-workflow-definitions と PaoBub） | 成果物の view に `as: "mindmap"`（親の欄を指定）を足し、PaoBub がマインドマップのエディタで開く | 0, 1 |
| E3 収支の道具 | 新規（business-case-core と business-case） | 前提表 AS（単位・出典・仮定の印）→ 10 年の損益・資金。NPV・IRR・回収年を小数で正確に。基本・楽観・悲観のシナリオ、トルネード図。数字ごとにどの前提から来たかをたどれる | 6, 8 |
| E4 スライドのアニメーション | 拡張（slide） | 物ごとの登場・強調・退場、クリックの順、画面の切り替え、グラフの系列ごと・マインドマップの枝ごとの登場、発表者ビュー。MP4・PDF・PPTX への書き出し | 10 |
| E5 生きた引用 | 拡張（artifact-references） | スライドや計画書の数字・図を収支やマインドマップの版に結ぶ。元が変わると「古い」と出て、更新できる | 9, 10 |
| E6 文書からスライドへ | 拡張（作業役の道具） | 計画書の章からスライドの骨子とアニメーションの順を提案。人はスライドの上の注釈で直す | 10 |

2026-11-21 時点の Open Editor Platform には、マインドマップがなく、スライドは「アニメーションの絵を埋め込む」だけで、物ごとの登場や画面の切り替えはありません。open-workflow-definitions の view は graph・kanban・timeline・calendar・table・form・matrix の 7 種です。

## PaoBub で確かめること

| 確かめること | 場面 | 前回の指摘との関係 |
| --- | --- | --- |
| 組織ごとの見せる範囲 | 提携先は「実行の計画」だけ見られ、収支は見られない | 新規 |
| 承認の決め方（複数の部署） | G2 は財務と法務・リスクの両方。片方が差し戻す場面も入れる | 白羽の 3 社承認の続き |
| 確かめ役の数字の検査 | 収支を前提から引き直して一致を見る。スライドと収支の版の一致も見る | 「数値のずれで判定する」の案 |
| 確かめ役が画像を見る | スライドの絵で文字の重なり・はみ出しを判定する | 直したものの確認 |
| 定義の更新を既存の Project に反映 | 途中で 1.0 → 1.1 に上げ、成果物の追加と受け入れ済みの再確認を確かめる | 直したものの確認 |
| 作業役の進み具合と上限 | 段階・残り時間・最新の絵がスレッドに出るか。自己チェックが上限で止まるか | 直したものの確認 |
| 種類ごとに専用のエディタで開く | マインドマップ・収支・スライドが表でなく専用のエディタで開くか | 「CAD が表で開く」の確認 |
| レビューへの画像の添付と作者名 | 経営会議の役員が参考の絵を貼って直しを頼む | 直したものの確認 |
| 依頼ごとのモデルの選択 | 収支の前提は高い努力量、マインドマップの枝は低い努力量 | 直したものの確認 |
| 引用の追跡 | スライドの数字 → 計画書 → 収支 → 前提 AS → 出典、をたどれるか | 新規 |

前回の指摘は「PaoBub ドッグフーディング：使いにくい点といい点」の文書と、その直し（paobub #333）です。各工程では、作業役の下書き → スレッドでの複数人の議論 → 注釈と手での直し → 承認、の流れを収録し、白羽と同じくメイキング動画にします。

## このフォルダーに入るもの（予定）

- `workflow.json`、`definition.json`（new-business-planning）
- `docs/`：工程ごとの成果物（マインドマップ、仮説、市場、事業モデル、実行の計画、収支、リスク、投資の判断、計画書、スライド、承認の記録、学び）

- `trace/`：引用と判断の記録、定義の変更の記録
- `assets/`：スライドの静止画（動画は大きいので入れない）
